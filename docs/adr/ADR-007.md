# ADR-007: Use Node 24 Across Local Development, Devcontainer, and CI

- **Status:** Accepted
- **Date:** 2026-10-20

## Context

The initial project plan specified Node 22 LTS across local development, `.devcontainer`, and GitHub Actions CI. During Phase 0 / M0 environment verification on the local Windows machine, the installed system Node runtime was found to be `v24.14.1` (`npm 11.17.0`), while local disk constraints made avoiding redundant runtime installations desirable.

## Decision

Switch the standard Node runtime version from **Node 22** to **Node 24** across local development, `.devcontainer/devcontainer.json` (`mcr.microsoft.com/devcontainers/typescript-node:24-bookworm`), and all GitHub Actions workflows (`actions/setup-node` with `node-version: '24'`), while setting `"engines": { "node": ">=20.19" }` in `package.json`.

## Reasons

1. **IWSDK Support:** `@iwsdk/create@1.0.1` and `@iwsdk/core` explicitly declare `"node": ">=20.19.0 <21.0.0-0 || >=22.12.0 <23.0.0-0 || >=24.0.0"` in their `engines` field.
2. **Contest & SDK Requirement:** Both the Meta VR Start Developer Competition 2026 and IWSDK require only `Node >= 20.19`.
3. **Local / CI Parity:** Running Node 24 in GitHub Actions and `.devcontainer` matches the local `v24.14.1` system runtime without requiring a separate portable Node 22 installation on disk.
4. **Playwright Compatibility:** Current Playwright releases officially support Node 22, 24, and 26.

## Consequences

- Zero extra disk space is consumed by a secondary Node runtime on the local machine.
- Local builds, `.devcontainer`, and GitHub Actions CI all run on the same major Node version (Node 24).
- `package.json` enforces `"engines": { "node": ">=20.19" }` to document the minimum supported floor.
